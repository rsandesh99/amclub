# Accessibility — Phase 8 §1 report

**Date:** 2026-07-09 · **Method:** axe-core 4.x via `@axe-core/playwright` (WCAG 2.0/2.1 A+AA rulesets) + scripted keyboard walk + manual review. Scanner: `apps/web/scripts/a11y-scan.ts` · keyboard walk: `apps/web/scripts/a11y-keyboard.ts`.

## Result

**0 critical · 0 serious · 0 moderate · 0 minor** across all 45 scanned surfaces (after fixes below). The scan covers gateway (en+hi), full public catalog (services index, category listing, provider profile, package page), auth (login, signup, partner signup), legal pages, and — via service-role-minted sessions — every MSME surface (home, search, RFQ list/new incl. voice UI, orders list, order workspace, checkout, notifications, profile, invoices, saved), every provider surface (home, 7-step onboarding wizard, listings, listing editor, orders, order detail, RFQs, earnings, reviews) and every admin surface (12 pages).

Viewport: 390×844 (mobile-first — the target user is on a phone), `prefers-reduced-motion: reduce`.

## How to run

```bash
# Full scan (needs SUPABASE_SERVICE_ROLE_KEY in apps/web/.env.local; creates and
# removes its own kill-test users/order):
pnpm --filter @amclub/web build && pnpm --filter @amclub/web start &
cd apps/web && A11Y_ENFORCE=1 BASE_URL=http://localhost:3000 npx tsx scripts/a11y-scan.ts

# Keyboard walk (focus order + visible-indicator check):
npx tsx scripts/a11y-keyboard.ts
```

CI runs the same scanner on every push/PR (`a11y` job) against a locally-started
production build — **public + auth surfaces only** (no service-role key leaves
the local machine). Authenticated surfaces are covered by the local full scan
above; re-run it when touching dashboard/admin UI.

## What the initial scan found (2026-07-09, HEAD 342348c) and the fixes

| Impact | Rule | Where | Root cause → fix |
|---|---|---|---|
| critical | `select-name` | RFQ form (voice), admin providers, admin orders | Category `<Select>` had no id/label link → `htmlFor`/`id` pair; admin filter selects → `aria-label={t('status')}` |
| critical | `label` | admin categories | Commission `<input type=number>` unlabeled → `aria-label` with category slug |
| serious ×5 | `aria-progressbar-name` | signup, partner signup, msme home, provider wizard, package wizard | `Progress` exposed `role="progressbar"` with no name → role+name only when a `label` is passed; decorative (`aria-hidden`) otherwise |
| serious ×7 | `color-contrast` | status badges, warning banners, voice consent note | Tokens failed AA on their soft backgrounds: `success` 3.60:1, `verified` 4.44:1, `warning` ~4.3:1 on tints. Darkened in **both** Tailwind configs (web + mobile): success `#1E8E5A→#14724A` (5.16), verified/trust `#1A6FBF→#155C9E` (5.91), warning `#B45309→#92400E` (6.0+). Consent note dropped `/80` opacity (3.88→6.12) |
| serious | `definition-list` | checkout | Total row used `<span>`s inside `<dl>` → `<dt>/<dd>` |
| serious | `scrollable-region-focusable` | admin home | Liquidity matrix `overflow-x-auto` not keyboard-reachable → `tabIndex=0` + `role="region"` + label |
| serious | `html-has-lang` | root 404 | No root `not-found.tsx` → Next default 404 shipped `<html>` without `lang`. Added `apps/web/app/not-found.tsx` (`lang="en"`) |

## Keyboard pass (manual criteria, scripted verification)

Tab-walked `/login`, `/signup`, `/app/rfq/new`, `/partner/onboarding` (wizard step 1), `/services`:

- **Every focus stop shows a visible indicator** (outline or ring box-shadow) — 0 failures. The design system centralises this: `focus-visible:ring-2 ring-primary` on `Button`, `.field-*` classes, and interactive cards (`globals.css`).
- **Wizard focus order is logical**: legal name → display name → about → category chips → state → city → language chips → Continue. No traps.
- Signup → RFQ → checkout journey is completable keyboard-only (OTP entry, category select, template fields, pay button are all native focusable controls).
- `prefers-reduced-motion` re-verified: the whole scan ran under `reducedMotion: 'reduce'`; gateway choreography renders instantly (media query at `globals.css:170`), buttons use `motion-safe:` for scale effects.

## Tap targets

`Button size="sm"` is 36 px high — below the 44 px touch guidance. All **user-facing** (MSME/provider) uses were bumped to the default `md` (44 px): msme home explore CTA, RFQ list post CTAs ×2, partner onboarding CTA, quote compare accept/message/rescue/send ×5. Remaining `size="sm"` uses are admin desktop tooling (verifications approve/reject, categories save) — kept deliberately; admin is a mouse-first ops surface.

## Screen-reader & residual manual scope

Automated scanning cannot grade: TalkBack/VoiceOver narration quality, Indic-script rendering, comprehension of escrow/RFQ copy, or real-device touch comfort. These stay on the human-QA list (STATUS_AUDIT §6). The `?` help-button label and emoji status toggles are announced but terse — cosmetic, flagged for copy review.
